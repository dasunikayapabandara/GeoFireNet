# GeoFireNet Security Testing Documentation

This document outlines the security testing protocols applied to the GeoFireNet system. Security testing ensures that the application is protected against unauthorized access, data injection, API abuse, and other common web vulnerabilities.

## Security and Vulnerability Testing

| Test Case ID | Test Scenario | Test Objective | Preconditions | Test Steps | Expected Result | Actual Result | Status | Priority | Notes / Recommendation |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| **ST-001** | CORS Configuration | Verify the API restricts origins to the authorized React frontend. | API is running. | 1. Send an OPTIONS request from an unauthorized Origin (`http://hacker.com`). | API rejects the request with CORS policy violation. | Pending execution | Pending | High | Prevents cross-origin attacks. |
| **ST-002** | Valid CORS Access | Verify the Vite dashboard can successfully query the API. | API and Dashboard running. | 1. Send request from `http://localhost:5173`. | API accepts request and returns CORS headers allowing the origin. | Pending execution | Pending | High | Core operational requirement. |
| **ST-003** | SQL Injection (Prediction Form) | Verify SQLAlchemy protects against SQLi in input fields. | Dashboard running. | 1. Enter `' OR 1=1; DROP TABLE alerts; --` in the Location field. | API treats it as a literal string. Database is not dropped. | Pending execution | Pending | Critical | ORM usage validation. |
| **ST-004** | SQL Injection (Query Params) | Verify API query parameters are parameterized. | API running. | 1. Request `/history?country=USA' OR '1'='1`. | API searches for literal country name "USA' OR '1'='1" and returns empty `[]`. | Pending execution | Pending | Critical | ORM usage validation. |
| **ST-005** | Cross-Site Scripting (XSS) in Dashboard | Verify React escapes user input rendered in the UI. | Dashboard running. | 1. Submit prediction for location `<script>alert('XSS')</script>`. 2. View History. | The script is rendered as plain text in the table, NOT executed by the browser. | Pending execution | Pending | High | Frontend security. |
| **ST-006** | XSS in Alert Descriptions | Verify dynamic alert descriptions don't execute HTML. | Alert generated. | 1. Force an alert with HTML in the message via API. 2. View Alerts page. | React renders the HTML tags as literal strings (`&lt;b&gt;`). | Pending execution | Pending | High | Frontend security. |
| **ST-007** | Directory Traversal | Verify the API doesn't allow reading arbitrary file paths. | API running. | 1. Send GET to `/api/../../../etc/passwd`. | FastAPI router returns 404 Not Found. | Pending execution | Pending | Medium | Framework safety. |
| **ST-008** | Environment Variable Exposure | Verify `.env` files are not exposed by the frontend or backend. | Vite/FastAPI built. | 1. Navigate to `http://localhost:5173/.env` or API. | Server returns 404. Variables are not leaked to the client bundle. | Pending execution | Pending | High | Secret management. |
| **ST-009** | Rate Limiting (Brute Force) | Verify the API limits excessive requests to prevent DoS. | API running. | 1. Use an automated script to send 5000 requests per second to `/predict`. | API responds with 429 Too Many Requests after threshold limit. | Pending execution | Planned | Medium | Resource protection. |
| **ST-010** | Missing Authentication Check | Verify protected routes (if any exist) require a valid token. | Auth implemented. | 1. Request `/alerts/1/resolve` without a JWT token. | API returns 401 Unauthorized. | Pending execution | Planned | High | Access control. |
| **ST-011** | Privilege Escalation | Verify a read-only user cannot resolve alerts. | Auth implemented. | 1. Login as "Viewer". 2. Send PATCH to `/alerts/1/resolve`. | API returns 403 Forbidden. | Pending execution | Planned | High | Role-Based Access Control (RBAC). |
| **ST-012** | Mass Assignment Vulnerability | Verify users cannot overwrite internal fields like `id` or `timestamp`. | API running. | 1. Send POST to `/predict` including `"id": 9999, "risk_score": 100`. | Pydantic model ignores unauthorized fields and generates a new ID. | Pending execution | Pending | High | Data integrity. |
| **ST-013** | HTTP Methods Restrictions | Verify endpoints only accept defined HTTP methods. | API running. | 1. Send POST request to `/history` (which is GET only). | API returns 405 Method Not Allowed. | Pending execution | Pending | Low | Framework enforcement. |
| **ST-014** | Information Disclosure in Errors | Verify production errors don't leak stack traces. | Trigger 500 error. | 1. Check HTTP response body. | Response is a generic {"detail": "Internal Server Error"}, no Python traceback. | Pending execution | Pending | High | OpSec. |
| **ST-015** | JWT Secret Key Strength | Verify the JWT signing key is cryptographically strong. | Code review. | 1. Check `config.py`. | `SECRET_KEY` is loaded from `.env` and is a >= 32 byte random string. | Pending execution | Planned | High | Cryptographic security. |
| **ST-016** | Token Expiration | Verify session tokens expire after a reasonable time. | Auth implemented. | 1. Obtain token. 2. Wait 24 hours. 3. Use token. | API returns 401 Unauthorized due to token expiry. | Pending execution | Planned | Medium | Session management. |
| **ST-017** | Password Hashing | Verify passwords are never stored in plaintext. | DB Admin. | 1. Query the `users` table directly in PostgreSQL. | Passwords appear as strong bcrypt hashes (e.g., `$2b$12$...`). | Pending execution | Planned | Critical | Data breach mitigation. |
| **ST-018** | Security Headers (HSTS, X-Frame-Options) | Verify the API sends standard security headers. | API running. | 1. Inspect HTTP headers of a response. | Headers include `X-Content-Type-Options: nosniff` and `X-Frame-Options: DENY`. | Pending execution | Planned | Medium | Protocol security. |
| **ST-019** | Third-Party Dependency Vulnerabilities | Verify Python dependencies are secure. | Repo. | 1. Run `pip-audit` or `safety check` on `requirements.txt`. | No known CVEs are found in FastAPI, SQLAlchemy, or scikit-learn versions used. | Pending execution | Pending | High | Supply chain security. |
| **ST-020** | Frontend Dependency Vulnerabilities | Verify Node.js dependencies are secure. | Dashboard repo. | 1. Run `npm audit` in the `dashboard/` directory. | Returns 0 critical or high vulnerabilities. | Pending execution | Pending | High | Supply chain security. |
| **ST-021** | Swagger UI Public Access | Verify if Swagger UI (`/docs`) should be exposed in production. | Production environment. | 1. Navigate to `/docs`. | Access is disabled OR requires basic auth to view in production. | Pending execution | Planned | Low | Surface area reduction. |
| **ST-022** | Open-Meteo API Key Leakage | Verify third-party API keys are not hardcoded. | Code review. | 1. Grep repository for "api_key" or "open_meteo". | No keys are hardcoded; all are loaded via `os.getenv()`. | Pending execution | Pending | High | Secret management. |
| **ST-023** | XML External Entity (XXE) | Verify the API is not vulnerable to XXE if XML is ever parsed. | API running. | 1. Send malicious XML payload to any endpoint. | API strictly accepts JSON (415 Unsupported Media Type for XML). | Pending execution | Pending | Low | Protocol restriction. |
| **ST-024** | CSRF Protection | Verify API endpoints mutating state are protected from CSRF. | API running. | 1. Submit POST from an external HTML form. | Request is blocked by CORS, or requires a Bearer token that isn't sent automatically via cookies. | Pending execution | Pending | High | Web vulnerability check. |
| **ST-025** | Predictable IDs | Verify database IDs can't be easily scraped. | API running. | 1. Analyze IDs in `/history`. | IDs are sequential integers (Acceptable for internal app) OR UUIDs (Preferred for public apps). | Pending execution | Pending | Low | Data enumeration. |
| **ST-026** | Large Pagination Attack | Verify an attacker cannot request 1,000,000 records to crash DB. | API running. | 1. Request `/history?limit=1000000`. | API limits the parameter to a max value (e.g., 1000) and returns that, or throws 422. | Pending execution | Planned | Medium | DoS mitigation. |
| **ST-027** | Sensitive Data Logging | Verify PI/Credentials are not logged to stdout. | App running. | 1. Login or perform actions. 2. Check server logs. | Passwords, tokens, and PII are redacted or omitted from console output. | Pending execution | Planned | High | Log sanitization. |
| **ST-028** | Local Storage Exposure | Verify sensitive data is not kept in browser LocalStorage. | Dashboard running. | 1. Inspect Chrome DevTools > Application > Local Storage. | Only theme preferences or non-sensitive UI state is stored; JWTs are in secure HttpOnly cookies (if used). | Pending execution | Planned | Medium | Client-side security. |
| **ST-029** | Input Type Validation | Verify integer fields strictly require integers. | API running. | 1. Send `{ "temp": "twenty" }` to `/predict`. | FastAPI returns 422 Unprocessable Entity for type mismatch. | Pending execution | Pending | Medium | Strong typing enforcement. |
| **ST-030** | Database Injection via Sort | Verify `ORDER BY` parameters cannot be exploited. | API running. | 1. If sorting is implemented, pass `sort=id; DROP TABLE alerts;`. | API rejects or strictly validates against an allowed enum of sortable columns. | Pending execution | Planned | Medium | SQLi variant check. |
